🏗️ Architecture Overview
Transform AI-generated flat spec files (logic + test combined) into a clean, maintainable Page Object Model. The POM separates what to test (specs) from how to interact with the UI (page objects).
💡 Goal: AI agents (Playwright's built-in planner, healer, generator) produce monolithic spec files. This architecture provides the target structure for refactoring those into reusable page objects, fixtures, and clean specs.

test('user can login', async ({ page }) => {
  await page.goto('/login');
  await page.fill('#email', 'user@test.com');
  await page.fill('#password', 'secret');
  await page.click('[data-testid="submit"]');

  loginPage, dashboardPage
}) => {

  await loginPage.loginAs(
    'user@test.com', 'secret'
  );

🔧 Page Fixtures
Fixtures are the backbone of POM in Playwright. They extend the base test object, instantiate page objects, and inject them into every spec — eliminating boilerplate.
fixtures.ts — The composition hub
One file that wires all page objects into Playwright's dependency injection system.
e2e/fixtures.ts 
import { test as base, Page, BrowserContext } from '@playwright/test';
import { LoginPage }      from './pages/login.page';
import { DashboardPage } from './pages/dashboard.page';
import { SettingsPage }  from './pages/settings.page';

// Declare fixture types for TypeScript autocompletion
type PageFixtures = {
  loginPage:     LoginPage;
  dashboardPage: DashboardPage;
  settingsPage:  SettingsPage;
  // Add new page objects here ↓
};

export const test = base.extend<PageFixtures>({

  // Each fixture receives `page` automatically from Playwright
  loginPage: async ({ page }, use) => {
    await use(new LoginPage(page));
  },

  dashboardPage: async ({ page }, use) => {
    await use(new DashboardPage(page));
  },

  settingsPage: async ({ page }, use) => {
    await use(new SettingsPage(page));
  },
});

// Re-export expect so specs only import from one place
export { expect } from '@playwright/test';
💡 How Fixtures Work
Playwright calls the setup function, passes the page object to use(), then tears down after the test.
1. Test requests loginPage fixture
↓
2. Playwright calls fixture factory with page
↓
3. Factory creates new LoginPage(page)
↓
4. Injected into test as loginPage param
🔗 Fixture Chaining
Fixtures can depend on other fixtures for authenticated states.
Advanced: authenticated fixture
type AuthFixtures = {
  authenticatedPage: Page;
  adminDashboard:    DashboardPage;
};

authenticatedPage: async (
  { browser }, use
) => {
  const ctx = await browser
    .newContext({ storageState: 'auth.json' });
  const page = await ctx.newPage();
  await use(page);
  await ctx.close();
},

adminDashboard: async (
  { authenticatedPage }, use
) => {
  await use(new DashboardPage(
    authenticatedPage
  ));
},
🏛️ Base Page Object
All page objects extend BasePage. It provides shared utilities — navigation, loading waits, error handling, and screenshot helpers — so every page object gets them for free.
base.page.ts
e2e/pages/base.page.ts 
import { Page, Locator, expect } from '@playwright/test';

export abstract class BasePage {
  readonly page: Page;

  constructor(page: Page) {
    this.page = page;
  }

  // ── Navigation ─────────────────────────────

  abstract goto(): Promise<void>;

  async waitForPageLoad(): Promise<void> {
    await this.page.waitForLoadState('networkidle');
  }

  async waitForURL(url: string | RegExp): Promise<void> {
    await this.page.waitForURL(url);
  }

  // ── Assertions ──────────────────────────────

  async assertVisible(): Promise<void> {
    await expect(this.pageContainer())
      .toBeVisible({ timeout: 10_000 });
  }

  /** Override to return your page's root locator */
  protected abstract pageContainer(): Locator;

  // ── Helpers ─────────────────────────────────

  async screenshot(name: string): Promise<void> {
    await this.page.screenshot({
      path: `screenshots/${name}.png`,
      fullPage: true
    });
  }

  async clickAndWait(
    locator: Locator,
    waitFor: string | RegExp
  ): Promise<void> {
    await Promise.all([
      this.page.waitForURL(waitFor),
      locator.click(),
    ]);
  }

  async fillAndTab(
    locator: Locator, value: string
  ): Promise<void> {
    await locator.fill(value);
    await locator.press('Tab');
  }
}
📄 Page Object Classes
Each page in your app gets one file. Selectors are defined as readonly locators, actions as async methods, and assertions as assert* methods.
login.page.ts — Full example
e2e/pages/login.page.ts 
import { Page, Locator, expect } from '@playwright/test';
import { BasePage }  from './base.page';
import { UserCredentials } from '../types/user.types';

export class LoginPage extends BasePage {

  // ── Selectors (readonly — never mutated) ────
  readonly emailInput:    Locator;
  readonly passwordInput: Locator;
  readonly submitButton:  Locator;
  readonly errorMessage:  Locator;
  readonly rememberMe:    Locator;
  readonly forgotPassword:Locator;

  constructor(page: Page) {
    super(page);
    // Prefer data-testid > role > text > CSS
    this.emailInput    = page.getByTestId('email-input');
    this.passwordInput = page.getByTestId('password-input');
    this.submitButton  = page.getByRole('button', { name: 'Sign in' });
    this.errorMessage  = page.getByRole('alert');
    this.rememberMe    = page.getByLabel('Remember me');
    this.forgotPassword= page.getByText('Forgot password?');
  }

  // ── Navigation ──────────────────────────────
  async goto(): Promise<void> {
    await this.page.goto('/login');
    await this.waitForPageLoad();
  }

  // ── Actions ─────────────────────────────────
  async loginAs(
    email: string, password: string
  ): Promise<void> {
    await this.emailInput.fill(email);
    await this.passwordInput.fill(password);
    await this.submitButton.click();
  }

  async loginWithCredentials(
    creds: UserCredentials
  ): Promise<void> {
    await this.loginAs(creds.email, creds.password);
  }

  // ── Assertions ──────────────────────────────
  async assertErrorMessage(msg: string): Promise<void> {
    await expect(this.errorMessage)
      .toHaveText(msg);
  }

  async assertLoginFormVisible(): Promise<void> {
    await expect(this.emailInput).toBeVisible();
    await expect(this.passwordInput).toBeVisible();
    await expect(this.submitButton).toBeVisible();
  }

  // ── Required abstract impl ───────────────────
  protected pageContainer() {
    return this.page.getByTestId('login-page');
  }
}
🧩 Reusable Components
Components model UI widgets that appear on multiple pages — navigation bars, modals, data tables, forms. They receive a Page or a scoped Locator as their root.
nav.component.ts
e2e/components/nav.component.ts
import { Page, Locator } from '@playwright/test';

export class NavComponent {
  private readonly root: Locator;

  constructor(page: Page) {
    this.root = page.getByRole(
      'navigation'
    );
  }

  link(name: string) {
    return this.root.getByRole(
      'link', { name }
    );
  }

  async navigateTo(name: string) {
    await this.link(name).click();
  }

  async assertActiveLink(name: string) {
    await expect(this.link(name))
      .toHaveAttribute('aria-current', 'page');
  }
}
table.component.ts
e2e/components/table.component.ts
export class TableComponent {
  constructor(private root: Locator) {}

  row(index: number) {
    return this.root
      .getByRole('row')
      .nth(index);
  }

  cell(row: number, col: number) {
    return this.row(row)
      .getByRole('cell')
      .nth(col);
  }

  async rowCount(): Promise<number> {
    return this.root
      .getByRole('row')
      .count();
  }

  async assertRowContains(
    row: number, text: string
  ) {
    await expect(this.row(row))
      .toContainText(text);
  }
}
Using components inside a page object
e2e/pages/dashboard.page.ts (using components)
import { NavComponent }   from '../components/nav.component';
import { TableComponent } from '../components/table.component';
import { ModalComponent } from '../components/modal.component';

export class DashboardPage extends BasePage {
  readonly nav:       NavComponent;
  readonly userTable: TableComponent;
  readonly modal:     ModalComponent;

  constructor(page: Page) {
    super(page);
    this.nav       = new NavComponent(page);
    this.userTable = new TableComponent(
      page.getByTestId('user-table')
    );
    this.modal     = new ModalComponent(page);
  }

  async goto() {
    await this.page.goto('/dashboard');
  }

  async openUserSettings(username: string) {
    await this.userTable.row(0)
      .getByRole('button', { name: 'Settings' })
      .click();
    await this.modal.assertVisible();
  }

  protected pageContainer() {
    return this.page.getByTestId('dashboard-page');
  }
}
📋 Spec Files
Specs import from fixtures.ts (not from @playwright/test directly). They describe behaviour in plain English. No selectors, no raw page.fill().
📌 Always import test and expect from your fixtures.ts, not from @playwright/test. This gives TypeScript knowledge of your custom fixtures.
login.spec.ts — Complete example
e2e/specs/login.spec.ts 
// ✅ Import from fixtures, not @playwright/test
import { test, expect } from '../fixtures';
import { TEST_USERS }   from '../helpers/test-data';

test.describe('Login', () => {

  test.beforeEach(async ({ loginPage }) => {
    await loginPage.goto();
  });

  test('should show login form on load',
    async ({ loginPage }) => {
      await loginPage.assertLoginFormVisible();
  });

  test('successful login redirects to dashboard',
    async ({ loginPage, dashboardPage }) => {
      await loginPage.loginAs(
        TEST_USERS.admin.email,
        TEST_USERS.admin.password
      );
      await dashboardPage.assertVisible();
  });

  test('invalid credentials show error',
    async ({ loginPage }) => {
      await loginPage.loginAs(
        'wrong@email.com', 'badpass'
      );
      await loginPage.assertErrorMessage(
        'Invalid email or password'
      );
  });

  test('empty submit shows validation errors',
    async ({ loginPage }) => {
      await loginPage.submitButton.click();
      await expect(
        loginPage.emailInput
      ).toHaveAttribute('aria-invalid', 'true');
  });

});
🔄 Refactoring Guide
Step-by-step process for converting AI-generated flat specs into POM. Follow this checklist for every spec file the AI planner generates.
⚡ Quick Refactoring Checklist
Step 1 — Extract Selectors
Move every page.locator(), page.fill() selector into the page object constructor.
Before → After
// Before (in spec)
await page.fill('#email', email);
await page.click('[data-testid="submit"]');

// After (in page object)
this.emailInput = page.getByTestId('email');
this.submitBtn  = page.getByRole('button',
  { name: 'Submit' });

// In spec
await loginPage.emailInput.fill(email);
await loginPage.submitBtn.click();
Step 2 — Wrap Actions
Group multi-step interactions into named action methods on the page object.
Before → After
// Before (3 lines in spec)
await page.fill('#email', 'u@t.com');
await page.fill('#pw', 'secret');
await page.click('button[type=submit]');

// After (1 line in spec)
await loginPage.loginAs(
  'u@t.com', 'secret'
);
Step 3 — Extract Assertions
Move expect() calls into named assert* methods on the page object.
Before → After
// Before
await expect(page.locator('.error'))
  .toHaveText('Invalid credentials');

// After — method on page object
async assertErrorMessage(msg: string) {
  await expect(this.errorMessage)
    .toHaveText(msg);
}

// In spec
await loginPage.assertErrorMessage(
  'Invalid credentials'
);
Step 4 — Update Imports
Change spec imports from @playwright/test to your fixtures.ts.
Import change
// ❌ Before (AI-generated)
import { test, expect }
  from '@playwright/test';

const page = ...; // raw page fixture

// ✅ After (POM)
import { test, expect }
  from '../fixtures';

// loginPage injected automatically
test('...', async ({ loginPage }) => {
  ...
});
⚠️ AI Healer compatibility: When Playwright's AI healer auto-fixes broken selectors, it rewrites them in the spec file. After refactoring, your selectors live in page objects — ensure the healer's config points to your pages/ directory so it patches them correctly.
